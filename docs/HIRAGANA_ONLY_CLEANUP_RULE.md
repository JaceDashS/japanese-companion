# 히라가나·카타카나-only 단어 정리 규칙

## 목적

커리큘럼에서 `expression` 전체가 히라가나-only 또는 카타카나-only인 학습 항목을 제거하고, 각 Day가 기존 순서와 20개 구성을 유지하도록 뒤의 항목을 당긴다. 항목이 앞쪽 Day로 이동할 때에는 원본 Day의 학습 상태가 함께 이동하도록 Day stage 메타데이터도 규칙에 따라 상속한다.

이 규칙은 현재 공식 에셋 구조인 `asset/*.json`의 combined JSON 파일에 적용한다.

현재 `scripts/remove-redundant-kana-items.cjs`의 기본 적용 대상은 `asset/jlpt-short-term.json`이다. N1 파일은 여러 Day 묶음과 중복 ID 네임스페이스를 사용하므로 `scripts/remove-redundant-kana-items-nested.cjs`로 각 묶음 단위의 당김과 Stage 메타데이터 상속을 처리한다.

## 삭제 기준

- `expression`이 히라가나 문자만으로 구성된 항목을 삭제한다.
- 기준은 유니코드 히라가나 범위(`U+3041`–`U+3096`)이다.
- `expression`이 카타카나 1개 이상과 허용 표기 기호만으로 구성되고 한자·히라가나가 없는 항목도 삭제한다.
- 카타카나-only의 허용 표기 기호는 장음부호 `ー`, 중점 `・`, 괄호·슬래시·공백 등 유니코드 구두점과 구분 기호다.
- 한자가 하나라도 포함된 표현은 삭제하지 않는다.
- 한자에 붙은 활용 어미/오쿠리가나가 있는 표현도 삭제하지 않는다.
  - 예: `怪しい`, `忙しい`, `大人しい`는 유지한다.
- 한자 또는 히라가나가 섞인 표현은 카타카나가 포함되어도 유지한다. 예: `アクセス（する）`, `データ内`.

## 인덱스 당김 규칙

1. 한 커리큘럼 파일의 Day들을 표시 순서대로 하나의 연속된 항목 목록으로 본다.
2. 삭제 대상 항목을 제거한다.
3. 삭제 지점 이후의 항목을 앞쪽으로 당겨 순서를 유지한다.
4. 각 Day는 기존처럼 20개 항목이 되도록 다음 Day의 항목을 앞 Day의 빈자리에 채운다.
5. 한 Day의 마지막 빈자리는 다음 Day의 첫 항목으로 채운다.
6. 이 당김은 필요한 만큼 다음 Day들까지 연쇄적으로 적용한다.
7. 마지막 Day에서 항목이 부족해지는 경우에는 새 항목을 만들지 않는다.

## 메타데이터 및 식별자

- 항목은 전체 객체 단위로 이동한다. `reading`, `meaningKo`, `problem`, 학습 결과, 메모 등 항목 내부 데이터는 유지한다.
- 이동한 항목의 `index`를 새 Day 내부의 1-based 위치로 갱신한다.
- 이동한 항목의 `id`도 새 위치에 맞춰 `d{day}-i{index}` 형식으로 갱신한다.
- 새로 구성된 Day의 `stage`, 복습일, 완료일 등 Day 단위 메타데이터는 그 Day 묶음의 **마지막 항목이 온 원본 Day**에서 상속한다.
- 따라서 뒤 Day의 항목이 앞 Day로 당겨지면 뒤 Day의 `stage`와 복습 메타데이터가 앞 Day에 상속될 수 있다.

## Stage 상속 예시

삭제 전 D36이 Stage 2이고 D37이 Stage 1인 상태에서 앞쪽 삭제로 D36의 마지막 항목이 D37에서 오면, 새 D36은 D37의 Day 메타데이터를 상속하여 Stage 1이 된다. 같은 방식으로 D35는 D36의 Stage를 상속한다.

즉, 새 Day의 stage는 단순히 기존 같은 번호의 Day 값을 유지하는 것이 아니라, 새로 채워진 20개 항목 중 마지막 항목의 원본 Day stage를 사용한다.
## 예시

현재 다음 항목을 삭제한다고 가정한다.

- D37 i15: `もったいない`
- D37 i20: `いろんな`
- D38 i4: `かわいそうな`

그러면 결과는 다음과 같다.

- D37 i15–i18은 기존 D37 i16–i19가 된다.
- D37 i19–i20은 기존 D38 i1–i2가 된다.
- D38 i1은 기존 D38 i3이 된다.
- D38 i2부터는 기존 D38 i5 이후 항목이 순서대로 당겨진다.
- D38의 남은 빈자리는 D39 앞부분으로 채운다.

## 적용 후 검증

- 삭제 대상 표현이 남아 있지 않은지 확인한다.
- 각 Day의 항목 수와 순서를 확인한다.
- 모든 항목의 `id`와 `index`가 새 Day 위치와 일치하는지 확인한다.
- 중복 `id` 또는 중복 `index`가 없는지 확인한다.
- JSON 파싱이 정상인지 확인한다.
